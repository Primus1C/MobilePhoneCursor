# StockAPI — Приходная накладная (`/incomingwaybills`)

HTTP-сервис **StockAPI**: создание приходных накладных (документ [[📄Приходная накладная]]).

---

## Авторизация

```
X-Api-Key: <токен учётной записи интеграции>
```

Неактивная или неизвестная [[Учетные записи интеграции|учётная запись]] → **401**.

Ограничения учётной записи:
- **склады** — ТЧ «Склады»;
- **поставщики** — иерархии групп из ТЧ «Поставщики».

Тело запроса и ответа — **JSON**, UTF-8. Даты поставщика и фильтры GET: `yyyy-MM-dd`. Реквизит **Дата** документа в POST/PUT/PATCH: `yyyy-MM-dd` или `yyyy-MM-ddTHH:mm:ss` (в ответе — `yyyy-MM-ddTHH:mm:ss`).

---

## Эндпоинты

| Метод | URL | Назначение |
|-------|-----|------------|
| GET | `/incomingwaybills` | Одна приходная или список с пагинацией |
| POST | `/incomingwaybills` | Создание и проведение приходной |
| PATCH | `/incomingwaybills` | Полная замена шапки и табличной части существующей приходной |
| PUT | `/incomingwaybills` | Добавление позиций в существующую приходную |
| DELETE | `/incomingwaybills` | Пометка приходной накладной на удаление |

---

## Пагинация (GET)

| Параметр | Синоним | Описание |
|----------|---------|----------|
| `page` | — | Номер страницы, с 1 (по умолчанию 1) |
| `pageSize` | `limit` | Размер страницы, 1–500 (по умолчанию 500) |

Ответ всегда содержит: `page`, `pageSize`, `totalItems`, `totalPages`, `items[]`.

## GET `/incomingwaybills`

**Назначение:** получить одну [[📄Приходная накладная|приходную накладную]] или список (поставщики из ТЧ «Поставщики» учётной записи). Параметры и проверки — **как у `GET /invoices`**.

**Запрос:**  
`GET /trade/hs/stock/incomingwaybills?...`

### Режим одного документа

Указан номер документа 1С и/или номер поставщика:

```
GET /incomingwaybills?number=000001234
GET /incomingwaybills?supplierNumber=INV-7788
GET /incomingwaybills?number=000001234&date=2026-08-25
GET /incomingwaybills?supplierNumber=INV-7788&sellerCode=1201
```

| Параметр | Синонимы | Описание |
|----------|----------|----------|
| `number` | `invoiceNumber`, `invoiceNo` | Номер документа `ПриходнаяНакладная` в 1С |
| `supplierNumber` | `supplierNo` | Номер поставщика (`НомерПоставщика`) |
| `date` | `invoiceDate` | Дата документа (`yyyy-MM-dd`) — уточнение |
| `sellerCode` | `supplierCode`, `code` | Код поставщика (опционально) |
| `alias` | `seller`, `supplier` | Псевдоним поставщика (опционально) |

Достаточно одного из номеров. Помеченные на удаление не возвращаются → **404**. Несколько совпадений → **400**.

### Режим списка

Номер не указан. Фильтр по поставщику и/или периоду:

```
GET /incomingwaybills?sellerCode=1201&dateFrom=2026-08-01&dateTo=2026-08-31&page=1&pageSize=50
GET /incomingwaybills?dateFrom=2026-08-01&dateTo=2026-08-31
```

| Параметр | Синонимы | Описание |
|----------|----------|----------|
| `sellerCode` | `supplierCode`, `code` | Код поставщика |
| `alias` | `seller`, `supplier` | Псевдоним / наименование |
| `dateFrom` | `from` | Начало периода (`yyyy-MM-dd`) |
| `dateTo` | `to` | Конец периода (`yyyy-MM-dd`) |

Период `dateFrom`/`dateTo` — **парой**; иначе **400**.

### Успешный ответ (200)

Дополнительно к полям накладной — данные инвойса-основания (`ВКД_Инвойс` / `_Инвойс`):

| Поле | Источник |
|------|----------|
| `invoiceNumber` | `_Инвойс.Номер` (номер 1С) |
| `invoiceIncomingNumber` | `_Инвойс.ВКД_НомерИнвойсаПоставщика` |
| `invoiceDate` | `_Инвойс.Дата` |

Если основание не заполнено — эти поля пустые строки.

```json
{
  "page": 1,
  "pageSize": 50,
  "totalItems": 1,
  "totalPages": 1,
  "items": [
    {
      "number": "000001234",
      "date": "2026-08-25T15:40:00",
      "seller": "Supplier Ltd",

      "warehouse": "Main",

      "supplierDate": "2026-08-25T00:00:00",

      "invoiceIncomingNumber": "INV-7788",

        {
          "item": "iPhone 15",
          "itemCode": "10045",

          "price": 350.5,
          "amount": 350.5,

        }

```

### Ошибки GET

| HTTP | Когда |
|------|--------|
| **401** | Нет / неверный `X-Api-Key` |
| **400** | Некорректные параметры; несколько документов |
| **404** | Документ не найден |
| **500** | Непредвиденная ошибка |

## POST `/incomingwaybills`

**Назначение:** создать и провести приходную накладную с партиями и остатками (флаг «Окончательно»).

**Запрос:**  
`POST /trade/hs/stock/incomingwaybills`

### Поля заголовка документа

| Поле JSON               | Синонимы                                                 | Обязательный | Описание                                                                                                                       |
| ----------------------- | -------------------------------------------------------- | ------------ | ------------------------------------------------------------------------------------------------------------------------------ |
| `sellerCode`            | `supplierCode`, `code`                                   | да\*         | Код поставщика (`Контрагенты.Код`)                                                                                             |
| `alias`                 | `seller`, `supplier`                                     | да\*         | Псевдоним или наименование поставщика                                                                                          |
| `warehouseCode`         | `warehouseId`                                            | да\*\*       | Код склада                                                                                                                     |
| `warehouse`             |                                                          | да\*\*       | Наименование склада                                                                                                            |
| `currency`              |                                                          | да           | Код валюты (`Валюты.Код` или `КодISO`)                                                                                         |
| `supplierNumber`        | `supplierNo`, `incomingNumber`, `incomingNo`, `incoming` | нет          | Номер поставщика (`НомерПоставщика`); при повторе для того же поставщика — ошибка                                              |
| `supplierDate`          | `incomingDate`                                           | нет          | Дата поставщика (`ДатаПоставщика`), по умолчанию — дата документа                                                              |
| `date`                  | `dateTime`, `documentDate`                               | нет          | Дата и время документа (`Дата`): `yyyy-MM-dd` или `yyyy-MM-ddTHH:mm:ss`; если не передано — **текущая дата сеанса** (POST)   |
| `note`                  | `comment`                                                | нет          | Примечание (до 200 символов)                                                                                                   |
| `invoiceNumber`         | `invoiceNo`                                              | нет          | Связь с инвойсом закупки (`ВКД_Инвойс`): номер `_Инвойс` в 1С **или** номер инвойса поставщика (см. ниже)                      |
| `invoiceSupplierNumber` | `invoiceSupplierNo`                                      | нет          | Номер инвойса поставщика (`Инвойс.ВКД_НомерИнвойсаПоставщика`); можно указать вместе с `invoiceNumber` для однозначного поиска |
| `items`                 |                                                          | да           | Массив позиций                                                                                                                 |

\* Нужен хотя бы один идентификатор поставщика (`sellerCode` / `alias` и синонимы).  
\*\* Нужен код или наименование склада.

Поставщик ищется **только** среди элементов в иерархии групп из ТЧ «Поставщики» текущей [[Учетные записи интеграции|учётной записи]] (см. также `GET /sellers`).

> [!attention] 
> **Не путать с GET:** в query-параметрах GET `invoiceNumber` / `invoiceNo` — синонимы номера **приходной** (`number`). В теле POST `invoiceNumber` относится к документу **`Инвойс`**, а `supplierNumber` — к номеру **приходной у поставщика** (`НомерПоставщика`). 

### Связь с инвойсом закупки (POST, необязательно)

Если **`invoiceNumber`** и **`invoiceSupplierNumber`** не переданы — реквизит `ВКД_Инвойс` приходной **не заполняется** (как при прямом приходе без инвойса).

Если передан хотя бы один из параметров:

- поиск `Инвойс` выполняется среди инвойсов поставщиков учётной записи;
- контрагент инвойса должен совпадать с **поставщиком** приходной из запроса;
- только **`invoiceNumber`**: сначала по номеру документа 1С (`Инвойс.Номер`), при отсутствии — по номеру инвойса поставщика (`ВКД_НомерИнвойсаПоставщика`);
- **`invoiceNumber`** и **`invoiceSupplierNumber`** вместе — оба условия (как при точечном поиске в API инвойсов);
- инвойс не найден или найдено несколько → **400**, документ не создаётся;
- при успехе в шапке приходной заполняется **`ВКД_Инвойс`**.

Параметра **`invoiceDate`** в POST **нет** (дата связанного инвойса возвращается только в GET в поле `invoiceDate`).

### Позиции `items[]`

| Поле | Синонимы | Обязательный | Описание |
|------|----------|--------------|----------|
| `itemCode` | `code` | да\* | Код номенклатуры |
| `item` | `name` | да\* | Наименование номенклатуры |
| `price` | `purchasePrice` | да | Цена закупки |
| `qty` | `quantity`, `count` | да\*\* | Количество (для несерийного товара) |
| `serial` | `series`, `imei` | да\*\*\* | Одна серия |
| `serials` | | да\*\*\* | Массив серий (каждая → отдельная строка с `qty = 1`) |

\* `itemCode` или `item`.  
\*\* Для товара **без** учёта по сериям.  
\*\*\* Для товара **с** учётом по сериям: `serial` и/или `serials`; количество всегда 1 на серию.

Тип номенклатуры — только «Товар». Повторяющиеся серии в одном запросе отклоняются.

### Цены `price`

Цена **каждой** позиции `items[]` записывается в `ЦенаЗакупки` как передана. У одной номенклатуры (`itemCode`) могут быть разные цены на разные серии: для этого передавайте **отдельные элементы** массива (каждый со своим `serial` и `price`). Поле `serials` создаёт несколько строк с **одной** ценой этого элемента.

В шапке заполняется `УчетнаяЗапись` текущей учётной записи API. Пока реквизит заполнен, при записи и проведении (в том числе при ручном перепроведении в 1С) цены из срезов инвойса **не подставляются** и не переставляются по возрастанию — пары серия–цена остаются как в запросе. Подробнее: [[📄Приходная накладная]].

## PATCH /incomingwaybills

**Назначение:** изменить существующую приходную: те же обязательные поля, что у POST (поставщик, склад, валюта, `items`), с **полной заменой** табличной части. Документ при необходимости отменяется и проводится заново с флагом [[Окончательно]].

**Идентификация документа** (query и/или JSON, как у GET одного документа):

| Параметр | Синонимы | Описание |
|----------|----------|----------|
| `number` | `invoiceNumber`, `invoiceNo` | Номер приходной в 1С |
| `supplierNumber` | `supplierNo`, `incomingNumber`, … | Номер поставщика |
| `date` | | День документа для уточнения поиска (`yyyy-MM-dd`; при `yyyy-MM-ddTHH:mm:ss` для поиска используется дата) |
| `sellerCode` | `supplierCode`, `code` | Код поставщика (опционально) |

Нужен **`number`** и/или **`supplierNumber`**. Поставщик в теле должен совпадать с контрагентом найденной накладной.

**Дата документа (`Дата`):** необязательные `date`, `dateTime`, `documentDate` — как в POST. Если не переданы, **дата документа не меняется**. Если переданы — записываются в реквизит **Дата** (с временем при формате `…THH:mm:ss`).

**Успешный ответ (200):** структура как у POST.

**Ошибки:** **404** — не найдена; **400** — валидация; **500** — сбой проведения.

---

## PUT /incomingwaybills

**Назначение:** добавить строки в **существующую** [[📄Приходная накладная|приходную]] (шапка и уже введённые строки сохраняются, кроме явно переданной даты документа).

**Идентификация:** те же параметры, что у PATCH.

**Тело:** обязателен массив **`items`** (формат как у POST). Остальные поля шапки не требуются.

**Дата документа:** если переданы `date`, `dateTime` или `documentDate` — обновляется реквизит **Дата**; иначе остаётся прежней.

**Успешный ответ (200):** структура как у POST (полный документ после изменения).

**Ошибки:** **404**, **400**, **500** — по тем же правилам, что PATCH.

---

## DELETE /incomingwaybills

**Назначение:** пометить существующую приходную накладную на удаление. Снимается проведение, сбрасывается флаг [[Окончательно]], ставится пометка удаления (одной записью; проверки «документ закрыт / не пустой» для API не действуют).

**Идентификация:** те же параметры, что у PATCH (`number` / `supplierNumber`, `date`, `sellerCode` / `alias`). Нужен **`number`** и/или **`supplierNumber`**. Параметры можно передать в query и/или в JSON. Массив `items` не требуется.

```
DELETE /incomingwaybills?number=000001234
DELETE /incomingwaybills?supplierNumber=INV-7788&sellerCode=1201
```

**Успешный ответ (200):** структура как у POST, плюс `deleted: true`, `posted: false`.

**Ошибки:** **404** — не найдена (в т.ч. уже помечена на удаление); **400** — нет идентификатора или ошибка записи; **500** — сбой сервера.

---

### Поведение в 1С

1. Создаётся [[📄Приходная накладная]] с заполненными шапкой и ТЧ «Товары»; в шапке записывается `УчетнаяЗапись` текущей учётной записи API (если ещё пуста).
2. Для каждой строки создаётся элемент справочника `Партии` с ценой из `items[].price`.
3. Документ записывается с флагом [[Окончательно]] и **проводится** — формируются остатки, поставки, долг поставщику. Цены строк **не** перезаполняются из инвойса.
4. Реквизит **`Инвойс`** (`ВКД_Инвойс`) заполняется только если в запросе указаны `invoiceNumber` и/или `invoiceSupplierNumber` и инвойс найден однозначно; иначе остаётся пустым.
