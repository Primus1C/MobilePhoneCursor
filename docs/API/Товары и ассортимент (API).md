# GET `/goods`

**Описание:**  
    получение списка номенклатуры типа **Товар**, которая за последние *N* месяцев имела ненулевой остаток на складах учётной записи **или** участвовала в движениях по этим складам. Метод возвращает карточные данные товара (без остатков и цен). Для остатков и цен используйте **GET /balances** и **GET /leftover**.

**Запрос**  
    GET /trade/hs/stock/goods

**Авторизация:**  
    заголовок `X-Api-Key` (токен [[Учетные записи интеграции|учётной записи интеграции]]).

---

## Параметры

| параметр | синонимы | описание | обязательный |
| --- | --- | --- | --- |
| `page` | — | номер страницы, начиная с 1 (по умолчанию `1`) | нет |
| `pageSize` | `limit` | размер страницы, 1–500 (по умолчанию `500`) | нет |
| `months` | `monthsCount` | глубина периода в месяцах, 1–120 (по умолчанию `12`) | нет |
| `warehouse` | — | наименование склада; без параметра — все склады учётной записи | нет |
| `warehouseCode` | `warehouseId`, `code` | числовой код склада (приоритетнее `warehouse`) | нет |

---

## Поведение

- авторизация — заголовок `X-Api-Key`, как у остальных методов Stock API;
- склад проверяется по списку, доступному учётной записи (для администратора API — по общим складам); при указании недоступного склада — **400** с текстом «Нет доступа к указанному складу.»;
- если у учётной записи не заданы склады — **400** («Для учётной записи не заданы склады.»);
- период: от `months` месяцев назад (начало дня) до текущей даты (конец дня);
- в выборку попадает номенклатура, у которой на отобранных складах выполняется **хотя бы одно** условие:
  - ненулевой остаток на **начало** периода;
  - **движение** в регистре `ОстаткиТовара` за период;
  - ненулевой **текущий** остаток;
- из справочника `Номенклатура` отбираются только элементы (не группы), не помеченные на удаление, с типом **Товар**;
- сортировка — по наименованию номенклатуры;
- при отборе по одному складу в ответ добавляются поля `warehouse` и `warehouseCode`.

---

```

GET /trade/hs/stock/goods?months=6&page=1&pageSize=100
GET /trade/hs/stock/goods?warehouse=Main
GET /trade/hs/stock/goods?warehouseCode=1&months=12
```

# GET `/goodGroups`

**Описание:**  
    папки справочника **Номенклатура**, в которые можно помещать новый товар. Возвращаются только конечные группы: без живых подчинённых папок, без пометки удаления и без признака **Выводить из ассортимента**. Товары внутри папки на отбор не влияют.

**Запрос**  
    GET /trade/hs/stock/goodGroups

**Авторизация:**  
    заголовок `X-Api-Key` (токен [[Учетные записи интеграции|учётной записи интеграции]]).

**Параметры:**  
    нет.

---

## Поведение

- список общий для всех учётных записей: склады и ассортимент учётной записи на выборку не влияют;
- папка попадает в ответ, если одновременно:
  - это группа;
  - нет пометки удаления;
  - **Выводить из ассортимента** = ложь;
  - нет подчинённых групп без пометки удаления (помеченные на удаление подпапки не считаются);
- сортировка — по наименованию;
- `fullName` — наименования всех групп иерархии от верхней к текущей, через `->`. Для группы верхнего уровня совпадает с `name`. Глубже шести уровней (текущая группа и пять родителей) путь не строится;
- код группы из `code` передаётся в **POST /goods** как `parentCode`.

---

## Пример

```
GET /trade/hs/stock/goodGroups
```

---

## Ответ (200)

```json
{
    "items": [
        {
            "code": "15497",
            "name": "Чехлы",
            "fullName": "Аксессуары->Чехлы"
        },
        {
            "code": "16002",
            "name": "Наушники",
            "fullName": "Наушники"
        }
    ]
}
```

### Элемент `items[]`

| поле | описание |
| --- | --- |
| `code` | код папки номенклатуры |
| `name` | наименование папки |
| `fullName` | путь от верхней группы к текущей через `->`; у группы верхнего уровня равен `name` |

---

## Ошибки

| код | когда |
| --- | --- |
| `401` | неверный или отсутствующий API-ключ |
| `500` | внутренняя ошибка |

---

| --- | --- |
| POST `/goods` | создание товаров в папке из этого списка |
| GET `/brands` | группы верхнего уровня (бренды), другой отбор |

# POST `/goods`

**Описание:**  
    создание нескольких элементов справочника **Номенклатура** за один запрос. Тело — объект с массивом `items`. Тип каждого товара — **Товар**. Ассортимент в запрос не передаётся: он копируется со склада строки. Склад берётся только из табличной части **Склады** текущей учётной записи (общие склады администратора API здесь не используются).

Строки обрабатываются по отдельности. Уже созданные товары не отменяются, если следующая строка ошибочна.

**Запрос**  
    POST /trade/hs/stock/goods  
    `Content-Type: application/json`

**Авторизация:**  
    заголовок `X-Api-Key` (токен [[Учетные записи интеграции|учётной записи интеграции]]).

---

## Параметры тела

| параметр | синонимы | описание | обязательный |
| --- | --- | --- | --- |
| `items` | — | массив товаров | да |
| `employeeCode` | `employeePin` | оператор склада на весь запрос; обязателен, только если для метода `goodsPOST` в учётной записи включена идентификация сотрудника | условно |

### Элемент `items[]`

| параметр | синонимы | описание | обязательный |
| --- | --- | --- | --- |
| `code` | `itemCode` | код товара, целое положительное число до 7 знаков; должен быть свободен во всём справочнике; если не передан, 1С присваивает следующий номер автоматически | нет |
| `name` | `item` | наименование, до 150 символов | да |
| `parentCode` | `groupCode` | код папки-родителя; см. GET `/goodGroups` | нет |
| `parent` | `group`, `parentName` | наименование папки-родителя | нет |
| `warehouseCode` | `warehouseId` | числовой код склада | одно из двух с `warehouse` |
| `warehouse` | — | наименование склада | одно из двух с `warehouseCode` |
| `sku` | `itemSku` | SKU, до 12 символов | да |
| `upc` | `itemUpc` | UPC, до 12 символов | нет |
| `jan13` | `itemJan` | JAN-13, до 13 символов | нет |
| `serialAccounting` | — | учёт по сериям; если не передан — `false`. Допустимы `true` / `false`, `1` / `0`, `yes` / `no` | нет |

Если в строке переданы и код, и наименование родителя, оба должны указывать на одну и ту же папку. То же для склада: код и наименование проверяются вместе.

Папка-родитель — любая группа без пометки удаления. Конечность папки (как в GET `/goodGroups`) при создании не проверяется.

Если в строке не переданы ни `parentCode`, ни `parent`, товар создаётся в группе из константы **«Группа новой номенклатуры»** (`АПИ_ГруппаНовойНоменклатуры`, общие настройки). Метод читает значение из одноимённого параметра сеанса; он заполняется из константы при старте сеанса, поэтому после смены константы новое значение подхватывается в новых сеансах. Если группа не задана, не является группой или помечена на удаление, строка не создаётся.

При записи строки заполняются:

- `ТипНоменклатуры` = **Товар**;
- `Ассортимент` = ассортимент склада этой строки;
- `УчетПоСериям` — из `serialAccounting`;
- код (из `code` или присвоенный автоматически), наименование, родитель, SKU, UPC, JAN-13.

Производитель, поставщик, вес и описание этим методом не задаются.

Если у склада строки не заполнен ассортимент, эта строка не создаётся. Текст ошибки: `У склада ХХХ не установлен ассортимент в 1С`.

Повтор того же кода во второй строке того же запроса даёт ошибку «уже существует», если первая строка успела записаться.

---

## Пример

```http
POST /trade/hs/stock/goods
Content-Type: application/json
X-Api-Key: <токен>

{
    "items": [
        {
            "code": "10025",
            "name": "Чехол Ozon, артикул OZ-15",
            "parentCode": "15497",
            "warehouseCode": "7",
            "sku": "OZ-15",
            "upc": "0194253401999",
            "serialAccounting": false
        },
        {
            "code": "10026",
            "name": "Наушники Ozon, артикул OZ-88",
            "parentCode": "16002",
            "warehouseCode": "7",
            "sku": "OZ-88",
            "serialAccounting": true
        }
    ]
}
```

---

## Ответ (200)

Все строки созданы: `success` = `true`, `error` пустой.

```json
{
    "success": true,
    "error": "",
    "items": [
        {
            "success": true,
            "error": "",
            "item": "Чехол Ozon, артикул OZ-15",
            "itemCode": "10025"
        },
        {
            "success": true,
            "error": "",
            "item": "Наушники Ozon, артикул OZ-88",
            "itemCode": "10026"
        }
    ]
}
```

Часть строк создана: код тоже **200**, `success` = `false`, в `error` текст `Создано товаров: N из M`. Успешные строки уже записаны в справочник.

| поле | описание |
| --- | --- |
| `success` | `true`, если создана каждая строка `items` |
| `error` | пустая строка, если созданы все; иначе сводка по запросу |
| `items` | результат по каждой строке запроса, в том же порядке |

### Элемент `items[]` ответа

| поле | описание |
| --- | --- |
| `success` | `true`, если эта строка записана |
| `error` | пустая строка при успехе; иначе `Строка N: ...` |
| `item` | наименование созданного товара |
| `itemCode` | код созданного товара |

---

## Ошибки

| код | когда |
| --- | --- |
| `401` | неверный или отсутствующий API-ключ (`success: false`) |
| `400` | тело не JSON, не передан обязательный сотрудник, нет массива `items`, массив пустой или это не массив, не создана ни одна строка |
| `200` | созданы все строки или только часть; ошибки строк лежат в `items[].error` |
| `500` | внутренняя ошибка при разборе запроса |

Типовые тексты при **400** на весь запрос:

| ситуация | `error` |
| --- | --- |
| нет поля `items` | `В теле запроса нет массива items.` |
| `items` не массив | `Поле items должно быть массивом.` |
| массив пустой | `Список items пуст.` |
| все строки с ошибками | `Не создан ни один товар.` Плюс `items[]` с текстами строк |

Тексты строки (после префикса `Строка N: `):

| ситуация | `error` |
| --- | --- |
| не объект | `Строка N: неверный формат позиции.` |
| код не число | `Код номенклатуры не числовой: '...'` |
| код не целое положительное | `Код номенклатуры должен быть целым положительным числом: '...'` |
| код длиннее 7 знаков | `Код номенклатуры длиннее 7 знаков.` |
| код занят | `Номенклатура с кодом N уже существует.` |
| не указано наименование | `Укажите наименование номенклатуры (name).` |
| наименование длиннее 150 символов | `Наименование номенклатуры длиннее 150 символов.` |
| родитель не передан и группа по умолчанию не задана | `Укажите код или наименование родителя (parentCode или parent) либо задайте группу новой номенклатуры в общих настройках.` |
| родитель не передан, группа по умолчанию не найдена или помечена на удаление | `Группа новой номенклатуры в общих настройках не найдена или помечена на удаление.` |
| папка не найдена | `Группа номенклатуры (родитель) не найдена.` |
| несколько папок с одним именем | `Найдено несколько групп номенклатуры с наименованием '...'. Укажите parentCode.` |
| не указан склад | `Укажите код или наименование склада (warehouseCode или warehouse).` |
| код склада не число | `Код склада не числовой: '...'` |
| склад не в ТЧ учётной записи | `Не найден склад (или нет доступа к указанному складу) с кодом '...'` либо то же с наименованием |
| несколько складов с одним именем | `Найдено несколько складов с наименованием '...'. Укажите warehouseCode.` |
| у склада нет ассортимента | `У склада ХХХ не установлен ассортимент в 1С` |
| не указан SKU | `Укажите SKU номенклатуры (sku).` |
| длинные коды товара | `SKU длиннее 12 символов.` / `UPC длиннее 12 символов.` / `JAN13 длиннее 13 символов.` |
| неверный признак серий | `Параметр serialAccounting должен быть булевым.` |

Нечисловой `parentCode` возвращает те же тексты, что и нечисловой код товара (`Код номенклатуры не числовой` и соседние).
